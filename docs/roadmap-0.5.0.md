# 0.5.0 章节中心写作台

## 版本定位

0.5.0 将章节目录、生成工作流、草稿版本和稿件导出连接为同一条写作链路。作者从章节
出发启动工作流，生成稿自动归入章节；手工修改保存为新版本，不覆盖历史正文或已接受
版本。

## 已完成范围

### 1. 章节驱动写作

- 直接生成和持久化工作流均支持 `chapter_id`。
- 工作流创建时校验章节属于当前作品和有效卷。
- 生成稿、AI 修订稿自动成为章节当前工作版本。
- 工作流结果记录章节 ID，便于从运行记录回到目录。

### 2. 当前版本与 Canon 版本分离

- `draft_id` 表示章节当前工作版本。
- `accepted_draft_id` 表示最近一次进入 Canon 的正式版本。
- 新版本创作期间继续导出上一版正式正文。
- 新版本接受后自动切换正式版本；拒绝当前稿时回退到上一版正式正文。

### 3. 作者手工编辑

- Web 可直接编辑章节正文，并保存为带父版本关系的新草稿。
- 手工版本保留差异比较、拒绝和 Canon 接受能力。
- 可选运行连续性与事实检查；原创性检查始终执行。
- CLI 支持 `novel-harness draft edit` 从本地 Markdown 文件创建手工版本。

### 4. 工作流交互

- 活跃工作流每两秒自动刷新。
- 前端展示运行错误，并支持失败重试和主动取消。
- 目录中的章节可直接打开工作流表单，填写本章目标、当前剧情和可选研究主题。

### 5. 导出与统计

- 新增 DOCX 导出，保留 Markdown 和 ZIP。
- 导出预览提供卷数、章节数、可导出章节、正文字符数和段落数。
- 工作台展示章节完成率，所有格式只读取 `accepted_draft_id`。

## 数据迁移

迁移 `20260629_0008` 为生成结果增加 `chapter_id`，为章节增加
`accepted_draft_id`，并将 0.4.0 中已接受章节的正式版本指针自动回填。

## 验收标准

- 从一个待创作章节启动工作流后，生成稿自动关联该章节。
- 新草稿不会替换可导出的已接受版本，接受后才切换正式版本。
- 手工编辑产生新 ID、父版本和递增修订号，原正文保持不变。
- 失败工作流可从失败步骤重试，运行中工作流可以取消。
- DOCX、Markdown 和 ZIP 的章节顺序、标题和正文一致。
- 全新 MySQL 可迁移到 head，`alembic check` 无差异。
- Python、TypeScript 静态检查及全量测试通过。
