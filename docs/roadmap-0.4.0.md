# 0.4.0 本地个人创作闭环

## 版本定位

0.4.0 面向本地单人使用，不以生产发布、多用户协作或高可用为目标。版本重点是把已经
生成和审阅的草稿组织成稳定目录，并导出可交付、可备份的作品。

## 已完成范围

### 1. 本地账户收口

- Auth 默认关闭手机号注册，前端不再展示手机号注册入口。
- 已有手机号账户仍可登录。
- `PHONE_REGISTRATION_ENABLED=true` 可在需要时重新开放手机号注册。
- 充值接口保持现状，不纳入本版本重构。

### 2. 卷章目录

- 每个新作品自动创建“第一卷”，历史作品首次打开目录时自动补齐。
- 支持新增、重命名和排序卷。
- 支持创建、重命名、排序章节并关联现有草稿。
- 章节包含待创作、创作中、已接受、已定稿四种状态。
- 关联草稿被接受为 Canon 后，章节状态自动更新为已接受。

### 3. 稿件导出

- Markdown 合集按卷和章节顺序生成。
- ZIP 交付包包含合集、逐章文件和 `metadata.json`。
- 只导出已接受或已定稿且正文草稿确实已进入 Canon 的章节。
- 无可导出章节时明确拒绝生成空交付包。

### 4. 本地运行与恢复

- `make local-up`、`make local-down` 提供统一启停入口。
- `make local-backup` 创建并校验 MySQL/MinIO 备份。
- 继续使用 `novel-harness ops restore` 和 `ops drill` 完成恢复与演练。

## 明确延期

- 手机短信、OAuth、项目成员、角色权限和分享审阅。
- 充值接口重构与财务级 Billing Outbox。
- 生产级高可用、集中监控和自动发布流水线。

## 验收标准

- 手机号注册请求在默认配置下返回 403，邮箱注册和已有账户登录不受影响。
- 卷章排序在刷新后保持一致，草稿与章节不能跨作品关联。
- 草稿接受后关联章节自动进入“已接受”状态。
- Markdown/ZIP 只包含已接受内容，且目录顺序稳定。
- 全新 MySQL 可以从首个 Alembic 迁移升级到 head，`alembic check` 无差异。
- Python、TypeScript 和 Go 检查全部通过。
